## Objetivo
Las operaciones del enunciado como una API limpia y documentada. Es la misma capa que después consumen las tools del agente: un solo camino hacia el dominio.

## Alcance
- [ ] Caso de uso `CreateBooking`
- [ ] Caso de uso `ListAvailableRooms` (salas libres en un rango)
- [ ] Caso de uso `GetRoomSchedule` (slots libres vs. ocupados de una sala)
- [ ] Caso de uso `CancelBooking` (solo del usuario autenticado)
- [ ] Caso de uso `ListMyBookings` — no está en el enunciado, pero sin él cancelar es impracticable
- [ ] Endpoints REST con DTOs y validación de entrada
- [ ] Contrato de error `problem+json` con un código estable por tipo de violación (`ROOM_CAPACITY_EXCEEDED`, `SLOT_TAKEN`, `MAX_DURATION_EXCEEDED`, …)
- [ ] OpenAPI navegable con springdoc
- [ ] Tests de integración por endpoint, camino feliz y de error

## Criterio de aceptación
El challenge completo se puede resolver desde Swagger UI sin tocar el chat. Cada error devuelve un código que el agente puede traducir a una frase útil para el usuario.
