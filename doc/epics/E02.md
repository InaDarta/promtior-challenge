## Objetivo
Guardar reservas con una garantía de la base de datos, no solo del código, contra la doble reserva.

## Alcance
- [ ] Migración Flyway V1: tablas `room`, `app_user`, `booking`
- [ ] Seed de las cinco salas con capacidades: **A=4, B=6, C=8, D=12, E=20** (el enunciado pide el límite pero no da los números — queda en ADR)
- [ ] Seed de User1 y User2 con password `TechnicalChallengePromtior` hasheada con BCrypt
- [ ] Constraint de exclusión en Postgres sobre sala + rango temporal (`btree_gist`), para que la doble reserva sea imposible incluso con requests concurrentes
- [ ] Adaptadores JPA de los puertos de repositorio definidos en el dominio
- [ ] Configuración de Testcontainers con Postgres para los tests de integración

## Criterio de aceptación
Un test de concurrencia lanza dos reservas simultáneas sobre el mismo slot y exactamente una gana; la otra recibe un error de conflicto tipado, no una excepción cruda de base de datos.
