# E05 — Agente conversacional y tool calling

## Objetivo
El núcleo evaluable del challenge: un asistente que opera el sistema de reservas **exclusivamente** a través de tools, y que nunca decide una regla de negocio por su cuenta.

## Proveedor de modelo
Primario **Google Gemini** vía `langchain4j-google-ai-gemini`, modelo `gemini-3.7-flash`, con el free tier de AI Studio (gratis, sin tarjeta). Fallback documentado: **Groq** con `llama-3.3-70b-versatile` a través del cliente OpenAI-compatible, que es el proveedor que sugiere el propio enunciado. Ollama para desarrollo offline.

Los tres detrás del mismo `ChatModel`: cambiar de proveedor es un perfil de Spring, no un cambio de código.

Criterio de la elección: este proyecto se juega entero en tool calling, y sobre ese eje Gemini Flash es más confiable que los modelos abiertos de Groq. Groq se mantiene porque el enunciado lo sugiere y porque su latencia hace que la demo se sienta instantánea.

## Criterio de aceptación
Conversaciones guionadas producen la tool correcta con los argumentos correctos. Una violación de regla devuelve una explicación clara y **ninguna** reserva creada: el modelo orquesta y explica, el dominio decide.
