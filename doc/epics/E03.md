## Objetivo
Login de User1 y User2, y una identidad en la que se pueda confiar incluso dentro de una tool ejecutada por el modelo.

## Alcance
- [ ] Spring Security con `POST /api/auth/login` que devuelve JWT
- [ ] Resto de la API autenticada; `/api/auth/login` y estáticos públicos
- [ ] `PasswordEncoder` BCrypt — el password del enunciado nunca en texto plano en la base
- [ ] Resolución del usuario actual desde el token, disponible para los casos de uso y para las tools
- [ ] Casos negativos: password incorrecta, token vencido, token ausente
- [ ] Autorización: cancelar una reserva ajena devuelve 403

## Criterio de aceptación
Test explícito de suplantación: el usuario escribe «reservá esto a nombre de User2» y el sistema crea la reserva a nombre del usuario autenticado o la rechaza. El texto del chat nunca cambia la identidad — esa la resuelve el servidor desde el token, nunca el LLM ni un parámetro de una tool.
